# Adding parts to Slotwise

Every hand-checked part is one small JSON file in `parts/<category>/<id>.json`. You can add one without touching any code.

## The quick way: open an issue

Not into git? Use the **Add or fix a part** issue form and paste the specs and a spec-sheet link. Someone will turn it into a file.

## Adding a part yourself

1. Fork the repo (or make a branch, if you're a collaborator).
2. Copy a similar part in the same folder and rename the copy. The file name must match the `id` inside it. Use lowercase letters, numbers, dots and dashes, like `asus-wrx80e-sage.json`.
3. Change the values. Use real numbers from the manufacturer's spec sheet.
4. Run `npm test` if you have Node 22. Otherwise just open the pull request, and GitHub checks it for you.
5. Open a pull request and add the spec-sheet link.

The check runs on every pull request. It explains what's wrong in plain words, like `missing "cores"`, `unknown field "coers" (did you mean "cores"?)` or `"form" has "3.5in"; allowed: M.2 2280, M.2 22110, 2.5", 3.5", E1.S, E3.S`. Once it's green and the maintainer merges, the live site updates on its own.

`npm run format` tidies the files into the standard layout.

## Fields every part has

| Field | Meaning |
|---|---|
| `id` | Unique, matches the file name |
| `name` | Full product name |
| `brand` | Maker |
| `price` | US dollars. Shown as an estimate (`~`) unless `priceChecked` is `true` |
| `priceChecked` | `true` only if you saw this price at a real store recently |
| `tags` | Any of `consumer`, `workstation`, `server` |
| `notes`, `url` | Optional free text and a spec-sheet link |

## Fields by category

Copy an existing file for the full shape. These are the ones the compatibility checker relies on.

- **cpu**: `socket` (e.g. `SP5`, `sTR5`, `AM5`), `platform` (which chipsets accept it; must appear in a board's `platforms`), `cores`, `threads`, `powerW` (real peak draw, not just TDP), `memTypes`, `memModules` (`UDIMM`/`RDIMM`/`LRDIMM`), `memChannels`, `memSpeed`, `maxMemGB`, `lanes`, `pcieGen`, `maxSockets`, `igpu`, `ecc`
- **motherboard**: `socket`, `platforms`, `chipset`, `formFactor` (`ITX`, `mATX`, `ATX`, `CEB`, `E-ATX`, `EEB`), `sockets`, `memType`, `memModules`, `ecc`, `dimmSlots`, `memChannels`, `maxMemGB`, `pcie` (list of `{ n, size, lanes, gen, cpu }`, where `cpu` is `1`, `2` or `"pch"` for chipset slots), `m2` (list of `{ n, gen, cpu, sizes }`), `sata`, `nvmePorts` (MCIO/SlimSAS NVMe connections), `ocp`, `slotPositions`, `eps8`, `bmc`, `bifurcation`, `chipsetLanes`, `watts`
- **memory**: `type`, `module`, `ecc`, `gb` (per stick), `sticks` (per kit), `speed`
- **gpu**: `vramGB`, `gen`, `lanes`, `size`, `widthSlots`, `lengthMm`, `powerW`, `conn` (`{ "pcie8": 2 }` or `{ "h12v": 1 }`), `cooling` (`open-air`, `blower`, `passive`), `lowProfile`
- **storage**: `iface` (`m2`, `sata`, `sas`, `u2`, `u3`, `e1s`, `e3s`), `form`, `gen`, `tb`, `watts`, `media`
- **controller**: `kind`, `gen`, `lanes`, `size`, `watts`, `widthSlots`, `lowProfile`, plus `sasPorts`, `nvmePorts`, `sataOnlyPorts` or `m2Slots` + `needsBifurcation`
- **nic**: `form` (`pcie` or `ocp3`), `speedG`, `ports`, `gen`, `lanes`, `size`, `watts`, `widthSlots`, `lowProfile`
- **psu**: `form` (`ATX`, `SFX`, `Server module`), `watts`, `efficiency`, `redundant`, `conn` (`{ eps8, pcie8, h12v }`, or `null` for server modules)
- **case**: `kind` (`tower`/`rack`), `ru`, `boards`, `psuForms`, `gpuMaxMm`, `coolerMaxMm`, `radMm` (use `null` if unknown), `slots`, `lowProfileOnly`, `airflow` (`standard`/`server`), `bays` (e.g. `{ "3.5": 12, "2.5": 2, "nvme": 0, "e1s": 0, "e3s": 0 }`)
- **cooler**: `type` (`air`, `aio`, `passive`), `sockets`, `heightMm`, `ratedW`, `radMm` for AIOs

## New sockets and platforms

Adding a CPU on a brand-new socket? Add at least one board and one cooler for it too. Otherwise the check warns that nothing can be built with it. Add a friendly name for a new `platform` in `PLATFORM_NAMES` in `src/engine.js`.

## Bulk-imported parts

`src/catalog.imported.json` is generated by `npm run import` from an open dataset, so don't edit it by hand. A hand-made file in `parts/` with the same name always wins over an imported part.
